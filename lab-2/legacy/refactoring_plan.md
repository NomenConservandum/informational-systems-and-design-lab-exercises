### Категория I. Идентичность персонажей, абстракция "Животное" и состояния (Вопросы 1, 2, 29, 30)

#### Вопрос 1. Что такое состояние Алёнушки? Основания из текста и триплетов
В тексте сказки и RDF-триплетах жизненный путь Алёнушки разделен на взаимоисключающие фазы, определяющие ее поведение и доступные действия:
1. **`ДЕВИЦА_СИРОТА`**: живет с братцем одни-одинешеньки, идет по полю на работу, оберегает брата от копытец, плачет под стожком после его превращения.
2. **`ЗАМУЖНЯЯ_ХОЗЯЙКА`**: выходит замуж за купца, живет в хоромах, ухаживает за козленочком.
3. **`ПЛЕННИЦА_НА_ДНЕ`**: обманута ведьмой, связана с тяжелым камнем на шее, лежит на дне реки ("тяжел камень на дно тянет, шелкова трава ноги спутала"). Единственное действие — жалобный отклик на голос братца.
4. **`СПАСЕННАЯ_ОЖИВШАЯ`**: освобождена от камня, омыта ключевой водой, наряжена в нарядное платье ("ожила и стала краше, чем была").

*Архитектурное решение*: В диаграмме классов хранение всего графа состояний через жесткий enum избыточно, если мы делаем отдельную диаграмму состояний (State Machine). В классе `Алёнушка` достаточно оставить признак физической доступности/жизни (`жива: Boolean`), а переходы состояний раскрыть на поведенческой диаграмме состояний (Этап 4).

#### Вопрос 2. Идентичность Иванушки и абстракция "Животное"
*Проблема*: В текущей версии `Козлёночек` наследует `Иванушка extends Человек`. Это нарушает принцип подстановки Лисков (Liskov Substitution Principle): козленок с биологической точки зрения не является человеком, но и не является обычным зверем, как `Конь`.
У Иванушки есть постоянная **идентичность (Identity)**: душа, разум, память, родственная связь с сестрой. Меняется лишь **физическая форма (Облик / Тело)**.
*Архитектурное решение*:
1. Ввести базовую иерархию существ:
   ```
   Персонаж (базовый субъект, носитель имени и воли)
     ├── Человек extends Персонаж
     │     ├── Алёнушка
     │     ├── Иванушка
     │     ├── Купец
     │     ├── Ведьма
     │     └── Слуга
     └── Животное extends Персонаж
           └── Конь (не владеет речью)
   ```
2. Для метаморфозы Иванушки использовать паттерн **State / Strategy** либо композицию:
   - Иванушка остается экземпляром `Человек` (или `Персонаж`), но содержит ссылку на текущее тело/обличие (`текущееТело: ФормаСущества` / `Облик`). // Учитывая, что облик может меняться и у ведьмы, то имеет смысл дать такое поле каждому персонажу
   - Либо класс `ЗаколдованныйКозлёночек` агрегирует `Иванушку`:
     `ЗаколдованныйКозлёночек o--> "1" Иванушка : воплощает личность`.
     Это объясняет, почему он умеет говорить, плакать и помнить сестру, в то время как обычный `Конь` этого делать не может.
   - Еще более изящное ОО-решение без лишнего усложнения: интерфейс `Говорящий` / `Разумный`, реализуемый `Человеком` и `Козлёночком`, в то время как `Конь` наследует чистое `Животное` без речевых способностей. // этот вариант представляется самым лучшим

#### Вопрос 29, 30. Булевы флаги vs состояние Козленка
Флаги `сохраняетЧеловеческийРазум`, `знаетОЗлодеянии`, `подУгрозойЗаклания` — классический антипаттерн "запах булевых флагов" (Boolean blindness).
*Решение*: 
- `сохраняетЧеловеческийРазум` убирается (это свойство его идентичности).
- `знаетОЗлодеянии` — знание факта (можно передавать через контекст или оставить `знаетПравду: Boolean`). // следует убрать
- `подУгрозойЗаклания` — это фаза жизненного цикла. Вся вариативность состояний Козленка (`СвободныйПасущийся` $\to$ `ОсознавшийБеду` $\to$ `ПриговоренныйКЗакланию` $\to$ `Расколдованный`) будет полноценно отображена на **Диаграмме состояний (State Machine Diagram)**, а из полей класса эти флаги удаляются.

### Категория II. Коммуникация, речевые акты и устранение избыточных методов (Вопросы 4, 5, 8, 11, 13, 14, 26, 27, 32, 33)

#### Проблема "локальных псевдометодов"
В текущей диаграмме созданы десятки узкоспециализированных методов:
- `попроситьНапиться(копытце)` — грубая ошибка: копытце не адресат просьбы.
- `предостеречьБратца(копытце)` — брат не является аргументом копытца.
- `выслушатьДоклад(слуга)`, `доложитьКупцу(купец, весть)`.
- `приказатьСлугамТочитьНожи()`, `послатьНаПоиски(слуга)`.
- `упрашиватьМужа(купец)`, `отпроситьсяНаРеку(купец)`.
- `зватьСестрицу(река)`.

#### Архитектурное решение в рамках ООП
Нужно ли плодить классы `Доклад`, `Просьба`, `Поручение`, `Диалог`?
- **Нет**, создавать для каждой фразы отдельный класс — это оверинжиниринг (overengineering). В ООП сообщение передается вызовом метода с параметрами либо строковым содержанием.
- **Обобщение**:
  Все речевые взаимодействия между персонажами сводятся к трем базовым операциям базового класса `Персонаж`:
  1. `сказать(кому: Персонаж, текст: String)` — передача информации (включает доклады, предупреждения, зов у реки).
  2. `попросить(уКого: Персонаж, просьба: String): Boolean` — запрос действия с возможностью согласия/отказа (просьба Иванушки к сестре напиться; просьба ведьмы к купцу зарезать козленка; просьба козленка к купцу отпустить на речку).
  3. `приказать(кому: Персонаж, распоряжение: String)` — директивное обращение вышестоящего к подчиненному (купец/ведьма слуге, ведьма слугам точить ножи).
- **Следствие**: Из классов `Алёнушка`, `Купец`, `Ведьма`, `Слуга`, `Козлёночек` удаляется до 12 дублирующих методов, а их логика становится чистой и полиморфной!

### Категория III. Локации и пространственное перемещение (Вопросы 12, 16, 18, 20, 24, 31)

#### Вопрос 16, 18, 20, 24. Места как первоклассные сущности (First-class entities)
В сказке постоянно фигурируют перемещения: "пошли по полю", "заманить на реку", "вытащить на берег", "отправить в поле", "окунуть в ключевую воду".
*Решение*:
1. Ввести абстракцию `Место` (`Локация`):
   ```
   abstract class Место
     ├── ДорогаВПоле
     ├── ХоромыКупца
     ├── Река
     └── БерегРеки
   ```
2. Обобщить пространственные действия персонажей:
   - `переместиться(куда: Место)` (вместо `бежатьЗаСестрой`, `сходитьНаРечку`).
   - `заманить(кого: Персонаж, куда: Место)` (у Ведьмы, вместо `заманитьНаРеку`).
   - `отправить(кого: Персонаж, куда: Место)` или `отпустить(кого: Персонаж)` (у Народа/Купца).
   - `искать(кого: Персонаж, где: Место)` (у Слуги, вместо `искатьКозлёнка(река)`).

### Категория IV. Физические взаимодействия с объектами и вещами (Вопросы 15, 17, 18, 19, 21, 22, 25)

#### Обобщение манипуляций с инвентарем
- **Класс `Вещь` (Артефакт / Предмет)**:
  `Камень`, `СетиШёлковые`, `Одежда` (платье).
- **Парные симметричные операции над вещами**:
  - `прикрепить(вещь: Вещь, кКому: Персонаж)` (Ведьма вешает камень на шею Алёнушке; Народ привязывает Ведьму к коню).
  - `снять(вещь: Вещь, сКого: Персонаж)` (Народ снимает камень с шеи Алёнушки).
  - `применить(вещь: Вещь, цель: Объект / Место)` (Народ закидывает сети в Реку).
  - `погрузить(кого: Персонаж, воЧто: ИсточникВоды)` (утопление в реке, омовение в ключевой воде).
- **Чистка атрибутов предметов**:
  - `Камень.тяжесть` $\to$ `Камень.вес: Double` (п. 21).
  - `Камень.привязанКШее: Boolean` $\to$ **удалить** (п. 22). Связь выражается ассоциацией `Камень [0..1] -- [0..1] Персонаж`. Если ссылка не `null`, значит, камень привязан.
  - `утопитьСКамнем(жертва, камень)` $\to$ `утопить(жертва: Персонаж, река: Река, груз: Вещь)` или комбинация `прикрепить(...)` + `погрузить(...)`.

### Категория V. Частные исправления и удаление псевдо-свойств (Вопросы 6, 7, 9, 10, 23, 34)

- **Вопрос 6 (`оплакиватьБеду()`)**: Беда — абстрактное эмоциональное состояние. Действие не меняет состояние системы и не производит объектов. **Удалить метод** либо выразить через базовое поведение выражения эмоций.
- **Вопрос 7 (`приютитьКозлёнка`)**: Обобщить до `приютить(кого: Персонаж)`. В дом купца принимаются и Алёнушка, и Козлёночек.
- **Вопрос 9 (`собратьНарод()`)**: Народ — внешняя группа. Купец вызывает метод `созвать(народ: Народ)` или `призватьПомощь()`.
- **Вопрос 10 (`верностьХозяину: Boolean`)**: Моральная оценка, не несущая программной семантики. **Удалить**.
- **Вопрос 23 (`разоблачена: Boolean`)**: Состояние разоблачения — производное (слуга донес купцу). **Удалить** флаг из Ведьмы; статус отражается в фазе сюжета.
- **Вопрос 34 (`кувыркнутьсяТрижды()`)**: Обобщить до `кувыркнуться(): Boolean`. Количество раз (3) — параметр или деталь реализации.

## 3. Новая целевая архитектура классов

### 1. Базовые абстракции
```plantuml
interface Персонаж {
    - имя: String
    - живой: Boolean
    + переместиться(куда: Место)
    + сказать(кому: Персонаж, текст: String)
    + попросить(уКого: Персонаж, просьба: String): Boolean
}

abstract class Человек implements Персонаж {
    - пол: String
    + приказать(кому: Персонаж, приказ: String)
    + надеть(вещь: Вещь)
    + снять(вещь: Вещь, сКого: Персонаж)
    + прикрепить(вещь: Вещь, кКому: Персонаж)
}

abstract class Животное implements Персонаж {
    - порода: String
    + издатьЗвук()
}
```

### 2. Персонажи
- `Алёнушка extends Человек`:
  - Атрибуты: `- замужемЗа: Купец [0..1]`
  - Методы: `+ выйтиЗамуж(купец: Купец)`, `+ ответить(брат: Персонаж, текст: String)`, `+ ожить()`
- `Иванушка extends Человек`:
  - Атрибуты: `- испытываетЖажду: Boolean`
  - Методы: `+ испить(источник: ИсточникВоды)`, `+ превратиться(облик: Облик)`
- `Козлёночек extends Животное` (агрегирует Иванушку как личность):
  - Атрибуты: `- цветШерсти: String`, `- личность: Иванушка`
  - Методы: `+ сказать(кому: Персонаж, текст: String)`, `+ кувыркнуться(): Boolean`, `+ расколдоваться(): Иванушка`
- `Купец extends Человек`:
  - Методы: `+ предложитьБрак(девица: Алёнушка)`, `+ приютить(кого: Персонаж)`, `+ отпустить(кого: Персонаж)`, `+ созвать(народ: Народ)`
- `Ведьма extends Человек`:
  - Атрибуты: `- текущийОблик: String`
  - Методы: `+ заманить(кого: Персонаж, куда: Место)`, `+ принятьОблик(человек: Человек)`, `+ погрузить(кого: Персонаж, куда: ИсточникВоды)`
- `Слуга extends Человек`:
  - Методы: `+ искать(кого: Персонаж, где: Место)`, `+ подслушать(источник: Персонаж): String`
- `Народ implements Персонаж`:
  - Методы: `+ созваться()`, `+ применить(вещь: Вещь, цель: Объект)`, `+ извлечь(кого: Персонаж, откуда: Место)`, `+ отпустить(кого: Персонаж)`

### 3. Пространство и вещи
- `abstract class Место`:
  - `Хоромы`, `Река`, `Берег`, `Поле`.
- `abstract class ИсточникВоды extends Место`:
  - `КопытцеВолшебное` (с эффектом трансформации), `Колодец`, `Ключ`.
- `abstract class Вещь`:
  - `Камень` (`- вес: Double`), `СетиШёлковые`, `Одежда`.
- `class Конь extends Животное`.
